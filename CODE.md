# Vitest Testing Patterns

## Test Structure

Organize tests alongside components:

```typescript
// Example test structure for game physics
import { describe, it, expect, vi } from 'vitest';

describe('PhysicsSystem', () => {
  it('applies gravity correctly', () => {
    const player = createPlayer();
    player.applyGravity(1);

    expect(player.yVelocity).toBeGreaterThan(0);
  });

  it('handles ground collision', () => {
    const player = createPlayer();
    player.checkGroundCollision();

    expect(player.isGrounded).toBe(true);
  });
});
```

## Mocking

```typescript
import { vi } from 'vitest';

// Mock functions
const mockFn = vi.fn();
mockFn.mockReturnValue(42);
mockFn.mockResolvedValue({ data: 'test' });

// Mock modules
vi.mock('@/services/api', () => ({
  authApi: {
    login: vi.fn(),
    getCurrentUser: vi.fn(),
  },
}));

// Mock timers
vi.useFakeTimers();
vi.advanceTimersByTime(1000);
vi.useRealTimers();
```

## Philosophy

**Modular & Hot-Swappable**:
- Each tool/library gets its own template file
- Templates have frontmatter for detection, but it's stripped before injection
- Only relevant practices are loaded into this file
- Keeps context lean and focused

**Extraction/Injection Model**:
- Templates live in `.claude/best_practices/` (version controlled)
- This file is regenerated on-demand (can be gitignored if desired)
- Frontmatter stays in templates (for tooling), content goes here (for context)

**Progressive Disclosure**:
- Universal rules: `.claude/memory/.claude-memory` (always loaded)
- Session essentials: `claude-quick-ref.md` (session start)
- Tech-specific: This file (on-demand via `/setup-stack`)
- Temporary focus: `/context:testing` (session-only)
